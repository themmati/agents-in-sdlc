フィルタリングの実装、命令の更新、スキルの更新、quality assurance (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にマージ処理を任せます。

> [!NOTE]
> 通常は、機能、命令の更新、スキルの更新、QA エージェントを複数の PR に分けます。このワークショップでは簡潔にするため、フィルタリングと品質確認の作業を同じ会話とブランチで進め、1 つの PR にまとめます。

このレッスンでは、次の内容を学習します。

- Agent Merge とは何か、マージのライフサイクルを自動化する仕組みを学びます。
- 機能の変更全体と検証の証拠を確認します。
- フィルタリングの PR を作成します。
- レビュー後に Agent Merge を有効にし、PR がマージされたことを確認します。

## シナリオ

フィルタリングのワークフロー全体を通して、Copilot を使って機能を計画、実装、検証してきました。Tailspin Toys では、マージの許可を開発者が管理しながら、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、プルリクエストをマージ可能な状態にするために必要な残りの作業を自動化します。有効にすると、Copilot は PR を妨げている問題に対応します。継続的インテグレーション (CI) チェックの失敗を修正し、レビューコメントに対応し、必要に応じてリベースした後、リポジトリで許可されていれば GitHub の自動マージを有効にします。

これまでは **Merge pull request** を自分で選択していました。Agent Merge にその処理を任せることもできます。有効にする前に作業をレビューし、マージしてよいと判断してください。

## Agent Merge で PR を管理する

すべてのコードを作成できたので、まとめてレビューし、PR を作成して、残りの処理を Agent Merge に任せます。

1. Codespace に戻ります。
2. `/agent` を入力してエージェントのダイアログを開きます。
3. 選択肢から **Default** を選び、<kbd>Enter</kbd> を押します。
4. `/pr create` コマンドを実行して、新しい PR を作成します。
5. `/pr agentmerge` を実行して Agent Merge を有効にします。
6. Copilot が PR の継続的インテグレーション処理を監視します。すべて成功すると、マージが実行されます。
7. Copilot が「PR #14 was squash-merged successfully.」のようなメッセージを表示したことを確認します。

> [!IMPORTANT]
> Agent Merge は、必須の承認、ブランチ保護、マージキュー、リポジトリ設定、権限の不足を回避しません。処理がブロックされた場合は、報告された理由を確認し、リポジトリで許可される場合は、レビュー済みの変更を手動でマージします。
