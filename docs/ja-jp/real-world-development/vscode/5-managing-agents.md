[← 前のレッスン: カスタムエージェント][previous-lesson]

GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、すべてのツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、会話に追加のプロンプトを送って作業を調整できます。エディターを離れる必要はありません。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル変更をレビューして承認します。
- 進行中のセッションでエージェントに指示を追加し、ハイコントラストモードに加えてライトモードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼があり、既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加することになりました。新しい会話を始めるのではなく、既存のセッションを調整して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行許可を求めるターミナルコマンドなどが表示されます。
3. ファイル編集が提案されると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、問題のないコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードの実装後、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは、これまでに変更したコンポーネント、スタイルの方針、local storage の使い方などのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. たとえば、エージェントが望まない方法でトグル UI を変更した場合は、チャット入力欄の隣にある **Stop** を選択して停止し、説明を追加して再依頼します。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりもすばやく調整できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、「トグルを 3 つにせず、ライトモードを既存の設定パネルに追加する」、「両方の切り替えにキーボードショートカットも追加する」のような追加プロンプトで、方針変更や範囲の拡張を依頼できます。

## 作業セットをレビューする

変更をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ方針に沿って、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存が行われていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して調整しました。ファイル編集を確認し、変更を承認または取り消し、コンテキストを保ったまま追加プロンプトで作業を広げました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を承認または取り消す方法。
- 追加プロンプトでセッションを調整する方法。

次の[レッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが行った変更をレビューします。
